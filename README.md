# Олимпиадная платформа

Готовое локальное веб-приложение для подготовки к олимпиадам по математике и информатике. Рабочая папка на этом компьютере: **`D:\OlympiadPlatform`**.

## Возможности

- Регистрация по логину и паролю, вход и выход, сохранение сессии.
- Шесть задач: по две лёгких, средних и сложных. Фильтр по сложности.
- Проверка числового ответа на сервере, мгновенный результат без перезагрузки. Отправка работает и без JavaScript.
- Один балл за первое верное решение каждой задачи. Повторные и одновременные запросы не увеличивают счёт.
- Личный кабинет с прогрессом и решёнными задачами.
- Личная история всех корректно оформленных попыток, включая неверные и повторные; по 20 записей на странице.
- Таблица всех участников, включая нулевые результаты: баллы, уникальные решённые задачи, общее число попыток, верные и неверные попытки. Повторные ответы входят в число попыток. При равном счёте — порядок по нормализованному логину, затем ID.
- На странице рейтинга также видны ваши последние пять попыток (условие задачи по ссылке, введённый ответ, результат и время) и ссылка на полную историю. Подробные ответы других участников остаются закрытыми.
- Русский адаптивный интерфейс, локальные стили и скрипты, без CDN, внешних шрифтов и сервисов.

## Технологии

Python **3.11+**, Flask, SQLite, SQLAlchemy / Flask-SQLAlchemy, Flask-Login, Flask-WTF, Werkzeug (scrypt), Jinja2, HTML5, CSS3, JavaScript, pytest. `requests` используется только для HTTP-проверок. Точные версии всех зависимостей закреплены в `requirements.txt`.

Разработка и проверка выполнены на Windows с Python 3.14.7. Node.js, Docker и сборка frontend не нужны.

## Быстрый запуск на этом компьютере

Окружение `.venv` уже подготовлено. Откройте PowerShell или вкладку **Terminal** в PyCharm и выполните:

```powershell
cd D:\OlympiadPlatform
.\.venv\Scripts\python.exe run.py
```

Откройте **http://127.0.0.1:5000**. Оставляйте терминал работающим, пока используете сайт. Для остановки нажмите `Ctrl+C`.

При первом запуске автоматически создаются база, секрет сессии и шесть задач. Учётные записи создайте через кнопку «Начать учиться». Паролей по умолчанию нет. Данные и баллы сохраняются после остановки.

## Установка с нуля на Windows

1. Установите Python версии 3.11 или новее с [официального сайта](https://www.python.org/downloads/windows/). При установке включите **Add python.exe to PATH**.
2. Разместите исходники непосредственно в `D:\OlympiadPlatform`. Не создавайте ещё одну одноимённую папку внутри. После скачивания ZIP перенесите содержимое распакованной папки, а не саму внешнюю папку.
3. В PowerShell выполните по очереди:

```powershell
cd D:\OlympiadPlatform
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe run.py
```

Активация окружения не обязательна: команды явно используют его Python. Это также обходится без изменения политики запуска PowerShell. Интернет нужен для установки пакетов; после установки сайт работает локально без интернета.

Если команда `python` не найдена, перезапустите терминал после установки Python либо укажите полный путь к `python.exe`. На текущем компьютере используется `python`, потому что системный `py` не обнаруживает установленную версию.

После клонирования репозитория порядок тот же: перейти в корень клона, создать `.venv`, установить `requirements.txt`, запустить `run.py`. Путь базы вычисляется относительно исходников и не зависит от текущей папки терминала.

## Запуск в PyCharm

1. Выберите **File → Open** и папку `D:\OlympiadPlatform`.
2. Откройте **File → Settings → Project: OlympiadPlatform → Python Interpreter** (название раздела немного зависит от версии).
3. Выберите **Add Interpreter → Add Local Interpreter → Existing** и файл:
   `D:\OlympiadPlatform\.venv\Scripts\python.exe`.
4. В списке конфигураций рядом с зелёным треугольником выберите **Olympiad Platform**. Готовая конфигурация находится в `.run/Olympiad Platform.run.xml` и ссылается на локальную `.venv`.
5. Нажмите зелёный треугольник **Run**. Альтернативно откройте `run.py`, нажмите правой кнопкой в редакторе и выберите **Run 'run'**.
6. В окне **Run** появится `Running on http://127.0.0.1:5000`. Откройте этот адрес в браузере.

Если готовая конфигурация ещё не появилась, переоткройте проект или создайте **Run → Edit Configurations → + → Python**: Script path — `D:\OlympiadPlatform\run.py`, Working directory — `D:\OlympiadPlatform`, Interpreter — Python из `.venv`.

Для остановки используйте красный квадрат **Stop** в PyCharm. Не запускайте второй сервер на том же порту. Исходный `main.py` теперь тоже запускает приложение, но основной файл — `run.py`.

## Проверки

Автоматические тесты:

```powershell
cd D:\OlympiadPlatform
.\.venv\Scripts\python.exe -m pytest -q
```

Они используют отдельные временные базы в `.pytest_tmp`, оставляют рабочую базу без изменений и проверяют регистрацию, вход, CSRF, защиту истории, отсутствие утечки ответов, валидацию, рейтинг, атомарность, параллельные запросы, повторное создание приложения и отсутствие дубликатов задач. CSRF в тестах включён. Проверка конкуренции запускает восемь независимых клиентов с общей файловой SQLite-базой; все восемь попыток должны сохраниться, а балл должен быть один.

Проверка настоящего HTTP-сервера с двумя пользователями и перезапуском процесса:

```powershell
.\.venv\Scripts\python.exe tools\http_smoke.py
```

Скрипт сам выбирает свободный локальный порт, запускает и останавливает два последовательных процесса, проверяет шесть одновременных запросов, историю, изоляцию, рейтинг и сохранение сессии. Отдельные данные и журнал остаются в `.local/http-check/`. Они не публикуются в Git. Встроенные проверки используют тестовые пароли только в изолированных базах.

## База данных и сохранность

Рабочая база: **`D:\OlympiadPlatform\instance\olympiad.db`**. При повторном запуске она открывается, а не пересоздаётся. Набор задач добавляется по уникальным постоянным `slug`, поэтому дубликаты не возникают.

Таблицы:

| Таблица | Содержание |
| --- | --- |
| `users` | Логин, нормализованный уникальный логин, хеш пароля, дата регистрации |
| `tasks` | Название, условие, сложность и правильный ответ |
| `attempts` | Пользователь, задача, отправленный ответ, результат и время |
| `solved_tasks` | Первые верные решения с уникальной парой `(user_id, task_id)` |

Включены внешние ключи, индексы, режим WAL и ожидание блокировки до 30 секунд. При отправке ответа транзакция `BEGIN IMMEDIATE` сохраняет попытку и уникальное решение вместе; `INSERT ... ON CONFLICT DO NOTHING` защищает от повторного начисления. Баллы — это количество строк `solved_tasks` конкретного пользователя, отдельного изменяемого поля баллов нет.

Время хранится в UTC, отображается по Москве (UTC+3). API возвращает ISO 8601 с суффиксом `Z`.

**Для резервной копии** остановите сервер и скопируйте папку `instance` в безопасное место. Не удаляйте её при обновлении исходников. Удаление базы стирает пользователей и прогресс. Изменение схемы существующей базы в будущих версиях потребует миграции; `create_all()` не заменяет миграции.

## Настройки и безопасность

`.env` не требуется для первого запуска. При необходимости скопируйте `.env.example` в `.env` и измените нужные значения:

| Настройка | По умолчанию | Назначение |
| --- | --- | --- |
| `SECRET_KEY` | Локальный случайный ключ | Ключ подписи сессии, не менее 32 символов |
| `COOKIE_SECURE` | `0` | `0` для локального HTTP, `1` только для HTTPS |
| `HOST` | `127.0.0.1` | Адрес прослушивания |
| `PORT` | `5000` | Порт сервера |

Без `SECRET_KEY` приложение один раз создаёт `instance/.secret_key`, а затем использует его повторно. Не публикуйте этот файл. Смена ключа сбросит активные сессии, но не прогресс в базе.

- Пароли хешируются Werkzeug scrypt, пароль ограничен 8–128 символами.
- Логины: 3–32 символа; русские/латинские буквы, цифры и `_`. Регистр не влияет на уникальность.
- Cookie: HttpOnly, SameSite=Lax; Secure включается для HTTPS. Постоянная сессия действует 14 дней.
- Все изменяющие запросы защищены CSRF, токен формы действует два часа. После истечения срока обновите страницу.
- Ответы принимаются только как числа (строка или JSON-число), максимум 64 символа. Допустимы знак, ведущие нули, пробелы по краям, дробная часть через точку или запятую. Формулы, экспоненциальная запись, NaN и Infinity отклоняются.
- Сравнение выполняется через Decimal на сервере. Клиент передаёт только `answer`.
- Правильные ответы не входят в каталог HTML или JSON. Пользователь видит собственные отправленные ответы в личной истории; готовые решения ему не выдаются.
- Личные данные читаются по защищённой сессии. Пользовательские `user_id`, `score` и `is_correct` не принимаются для изменения результата.
- Jinja экранирует HTML, ORM параметризует запросы; включены CSP и запрет встраивания в iframe. Подробности ошибок остаются в журнале сервера.

Встроенный сервер Flask предназначен для **локальной разработки**, а не публичного размещения. Режим debug выключен. Для интернет-размещения отдельно настройте WSGI-сервер, HTTPS, ограничения частоты запросов и резервное копирование. GitHub хранит исходники и не запускает Flask-приложение.

## Маршруты

| Метод и путь | Назначение | Доступ |
| --- | --- | --- |
| `GET /` | Главная | Всем |
| `GET, POST /register` | Регистрация | Гостям; POST с CSRF |
| `GET, POST /login` | Вход | Гостям; POST с CSRF |
| `POST /logout` | Выход | Авторизация и CSRF |
| `GET /tasks` | Каталог, параметр `difficulty=easy/medium/hard` | Всем |
| `POST /tasks/<id>/submit` | Отправка обычной HTML-формы | Авторизация и CSRF |
| `GET /profile` | Кабинет | Авторизация |
| `GET /history?page=1` | Личная история | Авторизация |
| `GET /leaderboard` | Все участники и их результаты | Всем |
| `GET /api/tasks` | Задачи без правильных ответов | Всем |
| `POST /api/tasks/<id>/submit` | Проверка ответа | Авторизация и CSRF |
| `GET /api/me` | Мой логин, баллы, список решённых задач | Авторизация |
| `GET /api/me/attempts?page=1` | Личная история, 20 строк на страницу | Авторизация |

API отправки принимает `Content-Type: application/json` и объект вида `{"answer":"42"}`. CSRF-токен берётся из `<meta name="csrf-token">` текущей HTML-страницы и отправляется в заголовке `X-CSRFToken`. Обязательно передавать session cookie. Ответ содержит `is_correct`, `awarded_points`, `score`, `message`.

Ошибки API — JSON с полем `error`: `400` — неверные данные/CSRF, `401` — нужен вход, `404` — задача или маршрут отсутствует, `405` — неверный метод, `413` — слишком большой запрос, `415` — неверный Content-Type, `503` — временная недоступность базы. Дубликат логина возвращает HTML с кодом `409`.

## Если что-то не запускается

- **No module named flask**: выбран другой Python. Запускайте `.\.venv\Scripts\python.exe run.py` и выберите тот же интерпретатор в PyCharm.
- **Порт занят**: остановите ранее запущенное приложение. Либо задайте `PORT=5002` в `.env` и откройте `http://127.0.0.1:5002`.
- **Не удаётся войти локально**: убедитесь, что `COOKIE_SECURE=0`, и используйте один адрес — `127.0.0.1`, не чередуя его с `localhost`.
- **Срок действия формы истёк**: обновите страницу и повторите отправку.
- **База временно занята**: повторите действие чуть позже; не удаляйте базу.

Технические справочники: [безопасность Flask](https://flask.palletsprojects.com/en/stable/web-security/), [SQLite в SQLAlchemy](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html).
